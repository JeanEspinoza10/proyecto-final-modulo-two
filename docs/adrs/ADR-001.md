# ADR-001: Por qué usar Arquitectura Hexagonal

## Estado
Aceptado

## Fecha
20226-05-15

## Contexto
Los datos y las reglas de negocio que maneja un sistema de gestión bancaria son altamente importantes y sensibles;  
por lo tanto, el flujo del sistema debe estar estrictamente controlado.
Además, este tipo de sistemas no debe depender excesivamente de una tecnología específica  
y debe contar con módulos y capas independientes, de modo que los cambios tecnológicos  
no afecten las reglas de negocio.

## Decisión
Teniendo en cuenta el contexto de las diferentes arquitecturas de software, como la monolítica y la hexagonal, 
siendo esta última la que más encaja para este sistema, debido a que permitirá separar las reglas de negocio 
de las diferentes tecnologías que se utilizarán. De esta forma, garantizamos que el sistema
bancario sea escalable y mantenible.

## Alternativas Consideradas
1. Arquitectura Monolítica
2. Arquitectura Hexagonal

## Consecuencias
### Positivas
- Aislar las reglas de negocio de los frameworks y tecnologías actuales, permitiéndonos 
una mayor escalabilidad del sistema.
- Facilitar la implementación de nuevos cambios debido a la separación de responsabilidades, como la base de datos, 
las reglas de negocio y los casos de uso.

### Negativas
- Incrementa la complejidad inicial del proyecto debido a la cantidad de capas y componentes necesarios.
